# PRD 2.1.4 · 启动种子装载与激活台账（增量）

| 项目 | 内容 |
| --- | --- |
| 版本 | 2.1.4（增量，基于 2.1.3） |
| 文档类型 | 增量 PRD（只描述本次变更，不复述已有功能） |
| 语言 / 技术栈 | 中文 / Tauri 2 + React 19 + Zustand，Windows 桌面端 |
| 影响范围 | 启动流程（前端 store 装载、App 渲染分支、Sidebar 计数）、新增激活台账持久化、后端启动路径（缓存直读 + 注册表探测顺序） |
| 现状规模基准 | 4214 字族 / 约 6000 字面 / 系统字体 166 / 已启用 169 / 已停用 4852 |

**一句话价值主张**：打开软件就能直接用上次启用的那批字体——剩余字体在后台安静读完，读完只刷新一次。

## 1. 版本目标

| 编号 | 目标 | 可度量口径 |
| --- | --- | --- |
| G1 | **首帧可用**：不必等全量读取完成，启动后即可使用上次启用 / 系统 / 分组内 / 快照内的字体 | 冷启动（4214 族库）从窗口可见到"可点击并成功套用字体" ≤ **1.5s**（p95 ≤ 2.5s） |
| G2 | **静默全量**：后台读取期间界面不逐批刷新、不闪骨架屏、不丢滚动位置，完成后一次性刷新 | 全量阶段主列表行数只发生 **1 次**跳变；主线程无 >100ms 的长任务（由读取引起） |
| G3 | **状态可信**：新增持久激活台账，侧栏在未知阶段显示 `…` 而不是错误的 0，避免"扫描期间把空数组写回" | 台账损坏 / 缺失时启动不弹错；侧栏未知态 0 次出现错误数字 |

**非目标（本次不做）**

- 不改字体解析算法、扫描并发度、`font-cache.json` 结构（只在启动时改变读取顺序）。
- 不引入数据库 / 常驻服务 / 开机预热进程。
- 不改分组、快照、标签、回收站的数据结构与已有交互。
- 不重新设计骨架屏视觉（仅决定何时使用它）。

## 2. 用户故事

| 编号 | 故事 |
| --- | --- |
| US-1 | **As 一位装了 4000+ 字族的用户**，I want 打开软件后立刻能用手上正在用的那批字体，So that 我不用为了改一行文案等十几秒。 |
| US-2 | **As 一位每天开合软件多次的用户**，I want 上次的启用状态被自动记住，So that 我不必每次重新启用同一批字体。 |
| US-3 | **As 一位在做设计排版的用户**，I want 读取过程中列表不要一跳一跳地长出来，So that 我能安心滚动和挑选，不会点错。 |
| US-4 | **As 一位关心"数字对不对"的用户**，I want 侧栏在还没读完时明确显示 `…` 而不是 0 或错的数，So that 我能分清"没有"和"还不知道"。 |
| US-5 | **As 一位临时试用字体的用户**，I want "启用至关闭"这类临时操作不被记进下次启动，So that 我的长期状态不会被试用行为污染。 |

## 3. 需求池

### 3.1 前置口径：种子集合（Seed Set）

种子集合 = 以下四类路径的**并集**，按路径去重（同一路径只算一次）：

| 来源 | 取值方式 | 备注 |
| --- | --- | --- |
| 上次已启用字体 | 持久台账 ∪ （注册表探测结果中「非系统目录 且 未被用户停用」的路径） | 两者都可信，取并集以兼容老版本用户（首次升级时台账为空） |
| 全部系统字体 | 注册表探测结果中的系统目录路径 | 用于让"系统字体"分类与套用立即可用 |
| 所有分组内字体 | `collections` / `collectionFaces` 中的族名与字面 | 需要有元数据才能渲染，故纳入种子 |
| 所有快照内字体 | `snapshots[].entries` 的 key → 路径 | 保证快照能立刻应用/切换 |

- 种子元数据**优先**从 `font-cache.json` 按路径 O(1) 取用；缓存未命中才按需解析该文件。
- 种子集合中的非系统字体：已在注册表中的跳过激活（避免无谓 Apply），缺失的才执行激活，使 G1 成立。

### 3.2 需求池表格

| 编号 | 优先级 | 需求 | 验收口径 |
| --- | --- | --- | --- |
| R-01 | P0 | 启动时先装载种子集合（§3.1），首帧即渲染并可用 | 首帧列表包含全部种子字族；点击「启用/停用」「套用」成功 |
| R-02 | P0 | 种子元数据走 `font-cache.json` 路径直读，不触发全量解析 | 种子阶段无字体文件解析耗时尖峰；缓存命中率在日志中可见 |
| R-03 | P0 | 并行执行注册表探测与缓存装载，取两者最短路径 | 探测失败不阻塞种子渲染（降级为"仅台账"种子） |
| R-04 | P0 | 全量读取在后台进行，**不再推送增量批次到主列表** | 全量期间列表行数不变；无 `scan:batch` 引起的重渲染 |
| R-05 | P0 | 全量完成后**一次性**刷新列表：不清空、不闪骨架屏、保持滚动位置（按族名锚点恢复） | 完成后可见族不变或偏差 ≤1 行；无白屏帧 |
| R-06 | P0 | 读取期间显示**非阻塞**进度提示（底部一条细进度 + 文案），不遮挡列表/侧栏点击 | 提示区域外点击全部生效；提示不占据列表可视区高度 |
| R-07 | P0 | 侧栏计数在读取中显示 `…`（详见 §5），宽度稳定不跳动 | 数字态与 `…` 态宽度一致（tabular-nums + 固定最小宽），切换时无横向抖动 |
| R-08 | P0 | 新增持久激活台账：只记录用户主动的持久启用/停用动作（详见 §6） | 台账内容与操作一一对应；会话级启用与系统字体为 0 条 |
| R-09 | P0 | 台账写入失败不影响操作，仅提示一次，且**不清空**历史台账 | 只读磁盘场景下操作仍成功、历史记录保留 |
| R-10 | P0 | 种子为空或装载失败时，自动回退到现有骨架屏 + 进度条流程 | 不弹错误对话框；最终仍能进入 ready 状态 |
| R-11 | P0 | 种子阶段禁用 `Ctrl+A` 全选（避免"全选"只选到局部集合） | 种子阶段按 `Ctrl+A` 选择集不变；全量完成后恢复 |
| R-12 | P0 | 全量读取结果不得覆盖种子阶段用户已做的启停决策（用户在读取中改了状态，以用户为准） | 读取中把 X 族停用 → 完成后 X 族仍为停用 |
| R-13 | P1 | 禁用"仅在全量结果上才安全"的批量操作入口：新建快照、清理快照缺失项（与现有 `snap.waitScan` 一致，读取中给一句提示） | 读取中点击 → 一句 info 提示，不执行、不写盘 |
| R-14 | P1 | 启动诊断日志：种子命中/未命中数、首帧耗时、全量耗时、注册表探测耗时 | 日志可 grep 出四项指标，用于回归对比 |
| R-15 | P1 | 读取失败时降级：保留种子列表可继续用，顶部给一条可重试提示 | 失败态不阻塞操作；点重试能再跑一次全量 |
| R-16 | P1 | 台账与 `deactivated` 冲突时以 `deactivated` 为准（用户明确停用过的不因台账被重新启用） | 构造冲突数据 → 启动后该路径为停用 |
| R-17 | P2 | 设置页展示"上次启动耗时 / 首帧耗时"，便于用户自查 | 数值与日志一致 |
| R-18 | P2 | 台账体积治理：超过阈值时按 LRU 修剪已不存在于本机的路径 | 台账条数上限受控，修剪不删除仍存在的路径 |

## 4. 启动流程交互时序

### 阶段 A：种子装载（目标 ≤1.5s）

| 步 | 内部动作 | 用户可见状态 | 可操作范围 |
| --- | --- | --- | --- |
| A1 | 窗口创建；读 `state.json`（台账 / collections / snapshots / deactivated / prefs）与 `font-cache.json` 索引；并行发起注册表探测 | 骨架屏（沿用现有视觉），文案提示"正在恢复上次启用的字体…" | 仅窗口级操作（移动/关闭） |
| A2 | 计算种子集合（§3.1）；缓存按路径取元数据；缓存未命中的少量文件按需解析 | 同上（此步通常 <300ms） | 同上 |
| A3 | 对种子内"注册表已存在"的路径跳过激活；对缺失的批量激活（不弹进度条） | 同上 | 同上 |
| A4 | **种子首帧**：渲染种子列表 + 侧栏（计数为 `…`）+ 底部读取进度条 | 列表出现，可正常滚动；底部一条细进度条 | 浏览、搜索、筛选、单族启停、详情面板、套用字体、快照应用/切换、删除指定字族；**Ctrl+A 禁用** |
| A5 | 进入阶段 B | 进度条开始推进 | 同 A4 |

> A4 若因激活耗时超过 800ms 仍未完成，也**先渲染列表**（激活在后台续跑），优先保证"看得见"。

### 阶段 B：后台全量读取

| 步 | 内部动作 | 用户可见状态 | 可操作范围 |
| --- | --- | --- | --- |
| B1 | 全量扫描（磁盘遍历 + 解析 + 缓存写入）；增量批次**只累加于内部缓冲区**，不进主列表 | 列表保持种子内容不变；底部进度条按真实 done/total 推进 | 与 A4 相同 |
| B2 | 用户在全量期间做的启停 → 记为"本地覆盖"，写入内部 pending 集合 | 该族状态立即变化；侧栏不更新数字（仍是 `…`） | 同 A4 |
| B3 | 若用户触发重扫（改目录 / 手动重扫）：合并到当前这一次，不排队、不重置种子列表 | 进度条 continuity；列表不清空 | 同 A4 |

### 阶段 C：完成与刷新

| 步 | 内部动作 | 用户可见状态 | 可操作范围 |
| --- | --- | --- | --- |
| C1 | 全量结果 → 叠加 B2 的"本地覆盖" → **单次** `set({ fonts, phase: "ready" })` | 列表在同一帧从种子切换为全量 | 同 A4 + **Ctrl+A 恢复** |
| C2 | 侧栏 7 项同一帧内由 `…` 切换为真实值 | 无中间态跳动 | — |
| C3 | 按族名锚点恢复滚动位置 | 可视区域基本不动 | — |
| C4 | 进度条收尾：成功显示"字体库已就绪"并在 1.5s 后淡出 | 短暂提示后消失 | 全部 |

**视觉约束**：整个过程**只允许出现一次骨架屏**（阶段 A 的 A1–A3）。C1 不闪骨架屏、不清空列表。若退出时正在阶段 B，不写任何"完成性"状态。

## 5. 侧栏计数展示规则

图例：`…` = 未知态（三点，tabular-nums，与数字态等宽）；`真实` = 现有口径现算；`0` = 真实为 0。

| 侧栏项 | 读取中（阶段 A/B） | 读取完成（阶段 C） | 读取失败降级 | 空库（完成但无字体） |
| --- | --- | --- | --- | --- |
| 字体库 | `…` | 真实 | 种子可算值（标注"部分"） | 0 |
| 收藏 | 真实 | 真实 | 真实 | 真实（可能为 0） |
| 最近导入 | 真实 | 真实 | 真实 | 真实（可能为 0） |
| 已启用 | `…` | 真实 | 种子可算值 | 0 |
| 启用至关闭（会话级） | `…` | 真实 | 种子可算值 | 0 |
| 已停用 | `…` | 真实 | 种子可算值 | 0 |
| 系统字体 | `…` | 真实 | 种子可算值 | 0 |
| 分组（每个分组行） | `…` | 真实 | 种子可算值 | `…`→0 |
| 标签（每个标签行） | `…` | 真实 | 种子可算值 | 0 |
| 快照（每份快照的条目数） | 真实 | 真实 | 真实 | 真实 |
| 回收站 | 真实 | 真实 | 真实 | 真实 |

**为什么这样切**：收藏 / 最近导入 / 快照条目 / 回收站来自 `state.json`，不依赖扫描；其余全部由 `fonts` 现算，未读完时给出的任何数字都是错的（尤其 0 会被读成"没有字体"）。

**补充口径**：`…` 必须是可读的省略号字符（不要用 `-` 或 `0`）；`…` 期间点击对应导航项不改变行为（进入该分类，列表仍是种子集合内可显示的项）。

## 6. 激活台账记录规则

| 动作 | 是否记录 | 说明 |
| --- | --- | --- |
| 单族「启用」 | ✅ 记录 add | 成功写盘后才记录；失败回滚不记 |
| 单族「停用」 | ✅ 记录 remove | 同上 |
| 批量启用 / 批量停用（含勾选后批量） | ✅ 按批原子记录 | 一批操作合并为一次写入，避免逐条落盘 |
| 「启用至关闭」（会话级临时启用） | ❌ 不记录 | 退出即撤销，不能影响下次启动 |
| 系统字体启停 | ❌ 不记录 | 由操作系统管理；台账中出现系统路径即视为脏数据，应忽略 |
| 分组「只启用这个分组」（切换语义） | ✅ 记录 | 被启用的记 add、被停用的记 remove（系统字体除外） |
| 快照「应用 / 切换 / 合并」 | ✅ 记录受影响的持久变更 | 切换=停用其他 + 启用快照内；合并=仅 add |
| 导入字体后的自动启用 | ✅ 记录 add | 属于持久状态 |
| 启动时"应用种子"本身 | ❌ 不记录 | 否则每次启动都自我强化写盘，台账永不收敛 |
| 删除字族 / 移入回收站 | ✅ 记录 remove | 防止下次启动尝试激活已不存在的路径 |
| 记录目标为系统字体路径 | ❌ 忽略 | 见上 |
| 台账写盘失败 | ⚠️ 保留内存态 + 提示一次 | 不清空历史台账；下次启动按上次成功写盘的内容恢复 |

**一致性要求**：台账 = 用户意图的快照，而非扫描结果的派生值。**禁止**再用"扫描结果中 active 的路径"覆盖台账（现有 `prefs.lastActivePaths` 在扫描未完成时被写成空数组的问题必须消除）。

## 7. 异常与边界场景

| # | 场景 | 期望行为 |
| --- | --- | --- |
| 1 | **首次启动**（无缓存、无台账） | 种子为空 → 自动回退骨架屏 + 进度条全量流程；总耗时不劣于 2.1.3（±5%）；不出现"正在恢复…"长驻文案 |
| 2 | **缓存版本升级作废**（`font-cache.json` 无法解析 / 结构不匹配） | 视为缓存不可用：种子元数据退化为"仅按需解析少量路径"；若超时则直接回退骨架屏流程；不删缓存文件、不报错弹窗 |
| 3 | **种子为空**（上次把所有可停用字体都停用了） | 种子 = 系统字体 + 分组 + 快照；仍走种子流程（系统字体必须立即可用）；若全为空则回退骨架屏 |
| 4 | **种子元数据命中率很低**（缓存缺失大量条目） | 按需解析上限内（例如 200 个文件）继续；超限则放弃种子阶段整体回退骨架屏，避免"伪快速启动"反而更慢 |
| 5 | **扫描中途用户启停某字体** | 立即生效并记入"本地覆盖"；全量完成后以用户操作为准，不被扫描结果回滚；侧栏计数保持 `…`，不闪中间值 |
| 6 | **扫描中途触发重扫**（改字体目录 / 手动重扫） | 合并进当前这次扫描（single-flight 语义不变）；**不清空**种子列表；进度条不重置到 0；完成后仍只刷新一次 |
| 7 | **批量启停断点存在**（上次批量中途退出，存在待续批） | 启动不自动续跑（保持现有"询问"语义）；台账只反映已成功那部分；种子装载不受影响 |
| 8 | **会话级启用残留**（崩溃退出，注册表中仍为启用但台账无记录） | 启动时以台账 + 注册表并集作为种子（保证"能看见并且能用"），但**不**把残留写入台账；界面按"已启用"呈现，用户下次显式停用才记录 remove |
| 9 | **字体文件被外部删除**（种子路径不存在） | 该路径从种子中静默剔除；台账中对应该路径标为"缺失"，下次启动不再尝试激活；不弹错误 |
| 10 | **注册表探测失败 / 超时** | 降级为"仅台账"种子；系统字体分类在完成阶段补齐；日志记录探测失败原因 |
| 11 | **种子阶段用户删除字族 / 移入回收站** | 允许；被删族从列表移除并记 remove；全量完成后不"复活"该族（除非文件仍在磁盘，此时以扫描结果为准并提示） |
| 12 | **台账文件损坏 / 不可写** | 损坏 → 以空台账启动（等价场景 1），保留坏文件副本供诊断；不可写 → 操作照常成功、提示一次、内存态维护到本次退出 |
| 13 | **全量完成瞬间用户正在搜索 / 滚动** | 搜索词与筛选条件保持；列表刷新不重置输入框；滚动位置按锚点恢复；不打断正在打开的详情面板/比较浮层 |
| 14 | **全量期间用户切到在线 / 回收站等其它视图** | 各视图各自正常；返回字体库时仍显示种子列表；完成刷新在任意视图下均只发生一次（后台完成也生效） |
| 15 | **软件在阶段 B 被关闭** | 不写"已完成"状态；缓存按已完成的部分正常落盘；下次启动种子流程不变 |

## 附录 B · 术语对齐

- 用户原话中的"已启用直到关闭"在现网文案为 **「启用至关闭」**（`side.activatedUntilClose`），本 PRD 统一用「启用至关闭」。
- "已启用"「已停用」为字族数口径，部分启用的字族会同时计入两者（合计可大于字体库总数），与现有 `side.countNote` 提示一致。
- 本文中"种子"= 首帧即可用的字体集合；"台账"= 持久激活记录文件。
