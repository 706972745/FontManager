# 修复说明 · 2.1.7 · 静默安装（/S）与选包

> **这是什么**：2.1.6 合同核对时发现、但**故意留到 2.1.7 修**的 4 处缺陷的执行说明。
> **为什么留到 2.1.7**：三处都在安装器/更新链路上，2.1.6 改任何一处都要重出包 + QA 重验，
> 而用户此刻正在装 2.1.6 看启动页界面（2.1.6 的主诉求是启动页提亮）。判定见 team-lead 2026-11-14。
> **谁能直接照着做**：每一条都是「文件:行号 / 现状 / 改法 / 验证方法」，不需要再回看上下文。

**一句话总结风险**：现在的安装器在 `/S`（静默）模式下有一个分支会**弹窗等人点**（无人值守 = 挂死）。
另一处「静默失败」的真实机制是**同一件事的延伸**：`MessageBox` 在 `/S` 下不自动消失，`update.rs` 的
`Start-Process -Wait -PassThru` 会一直等 → 永久挂住。

> **⚠️ 事实更正（2.1.7 QA 实测，2026-11-14）**：本文件最初写「有一个分支失败却返回退出码 0，
> `update.rs` 会把它当成功去删包重启」——**这句是错的**。裸 `Abort` / `Quit` 在 `/S` 下实测退 **2**
> （不是 0），`update.rs` 的 `ExitCode -eq 0` 从未被它骗过。`SetErrorLevel 1` 的价值是**把契约写显式**，
> 不依赖 NSIS 未文档化的默认值（默认值一旦变化就会变成真正的「报成功但没装好」）。

## E-1 · 旧版卸载失败时弹窗（仅 GUI 路径）

**文件**：`src-tauri/windows/installer.nsi`　**行**：`588-617`（已改，2.1.7；代码与第一轮一致，本轮只把注释改成实话）

> **⚠️ 可达性实测（NSIS 3.11，2026-11-14）**：这段在 `Function PageLeaveReinstall` 里，
> 而它是 `Page custom PageReinstall PageLeaveReinstall`（`:347`）的**页面 leave 回调**。
> 用探针实测：`/S` 下 **`Page custom` 的 create / leave 回调都不会被调用**（只有 Section 执行，
> `.onInit` 里 `IfSilent` 为 TRUE）。所以这段只覆盖 **GUI 的「重装 / 先卸载再装」路径**，
> **不是静默更新的保护**。`${If} ${Silent}` 分支属防御性代码（防的是将来把卸载逻辑挪进
> Section / `.onInit` 这类 `/S` 会执行的位置）。
>
> 静默更新的真实失败面在 **`:901` / `:933`**（见 E-2）。

现状（原始，`583-592`）：

```nsis
      ; User cancelled NSIS uninstaller? return to select un/reinstall page
      ${If} $0 = 1
        Abort
      ${EndIf}

      ; Other errors? show generic error message and return to select un/reinstall page
      MessageBox MB_ICONEXCLAMATION "$(unableToUninstall)"   ; ← 589：无 Silent 保护
      Abort
    ${EndIf}
  reinst_done:
FunctionEnd
```

**问题**：`$0` 是旧卸载器的返回码。既不是「用户取消」（1）也不是 WiX 的 1602 时，落到这一行。
`MessageBox` **不受静默模式抑制**（NSIS 的 `MessageBox` 在 `/S` 下照常弹窗并阻塞）——
**但这段代码本身在 `/S` 下不会执行**（页面回调不跑，见上方可达性实测），
所以它今天造成的实际影响只有 GUI 路径；写它是为了**不让 GUI 失败时静默无提示、也为了防未来重构**。
另外 `Abort` 之后的退出码不该依赖模板默认值（模板里没有 `SetErrorLevel`）。

**改法**（照 E-3 的形态，静默走 stderr + 置错误码）——**已落地，且注释已改成实话**：

```nsis
      ; Other errors? 静默模式下绝不能弹窗（update.rs 走 /S 无人值守，弹窗 = 挂死）
      ${If} ${Silent}
        System::Call 'kernel32::AttachConsole(i -1)i.r0'
        ${If} $0 <> 0
          System::Call 'kernel32::GetStdHandle(i -11)i.r0'
          System::call 'kernel32::SetConsoleTextAttribute(i r0, i 0x0004)'
          FileWrite $0 "$(unableToUninstall)"
        ${EndIf}
        SetErrorLevel 1
        Abort
      ${Else}
        MessageBox MB_ICONEXCLAMATION "$(unableToUninstall)"
        Abort
      ${EndIf}
```

**验证**：
1. 静态：`grep -n "MessageBox" installer.nsi` 的每一处都要有明确的静默语义。当前 4 处：
   `:603`（E-1，在 `${Else}` 内）、`:659`（`ZfmDirLeave` 目录页 leave 回调，**页面回调，`/S` 不可达**）、
   `:868`（E-3 样板，在 `${Else}` 内，但本仓库 `ALLOWDOWNGRADES=true` → 该块不参与编译）、
   `:971`（E-2 的 EdgeUpdate 通道，在 `${Else}` 内，但 `MINIMUMWEBVIEW2VERSION=""` → 不参与编译）。
   → 静态口径之外必须叠加**可达性**判断，否则会得出「已经保护了静默路径」的错误结论（这正是 2.1.7 第一轮的教训）。
2. 动态：造一个「旧卸载器返回非 0/1/1602」的现场（把 `$INSTDIR\uninstall.exe` 换成一个 `exit /b 5` 的假 exe），
   跑 GUI 安装器走「重装/先卸载再装」页，断言：弹窗出现且点掉后安装中止。
   （**不要**用 `/S` 验证这条 —— `/S` 下回调不执行，测了也测不到。）

## E-2 · WebView2 安装失败：静默下弹窗阻塞（最坏的一类失败）

> **⚠️ 落点勘误（2.1.7 QA 复核，2026-11-14 —— 必读，否则会像第一轮那样改了个不参与编译的块）**
>
> 本文最初指的 `:943-944`（`MessageBox … MB_ABORTRETRYIGNORE` + `Quit`）位于
> `!if "${MINIMUMWEBVIEW2VERSION}" != ""`（`:938`）**里面**。而 tauri 渲染出来的
> `rust-target/release/nsis/x64/installer.nsi` 里是：
> ```
> !define INSTALLWEBVIEW2MODE "downloadBootstrapper"   ; ← 激活的分支
> !define MINIMUMWEBVIEW2VERSION ""                    ; ← 空 → 上面那个 !if 恒假
> ```
> 因为本仓库 `tauri.conf.json` **没有配置 `minimumWebview2Version`**，所以 `:938-980` 整块
> **不参与编译** —— 在那里做任何修改都**等于没改**（2.1.7 第一轮就踩了这个坑）。
>
> **真正会编译、会执行的 WebView2 失败分支只有两处**，都在
> `!if "${INSTALLWEBVIEW2MODE}" == "downloadBootstrapper"`（`:892`）激活的那段里：
> - **`:901`** — bootstrapper **下载**失败（`NSISdl::download` 返回非 success）
> - **`:933`** — bootstrapper 下回来了，但 **安装**（`ExecWait`）返回非 0
>
> 两处原本都是裸的 `Abort "$(webview2AbortError)"`，**没有 `SetErrorLevel`**。
> `:938-980` 那块（EdgeUpdate 通道）**保留**（给将来配了最低版本的构建用），但它在当前构建里是死代码。

**文件**：`src-tauri/windows/installer.nsi`　**行**：`901` 与 `933`
（2.1.7 加完注释后的实际行号是 **`:917-918`** 与 **`:953-954`**；本文沿用 `:901/:933`
这个「加注释前的原行号」，方便与 QA 报告对齐）

现状（原始，`:899-902` 与 `:931-934`）：

```nsis
        ${Else}
          DetailPrint "$(webview2DownloadError)"
          Abort "$(webview2AbortError)"      ; ← 901：无 SetErrorLevel
        ${EndIf}
...
        ${Else}
          DetailPrint "$(webview2InstallError)"
          Abort "$(webview2AbortError)"      ; ← 933：无 SetErrorLevel
        ${EndIf}
```

**问题（按实测口径，原文写的「退出码 0」是错的）**：
1. **真病是挂死，不是误判成功**：`Abort` / `Quit` 的退出码实测取决于 NSIS 的**未文档化默认值**
   —— 无 `SetErrorLevel` 时 `/S` 下退 **2**（不是 0），所以 `update.rs` 的 `ExitCode -eq 0`
   从来没有把它当成功过。真正致命的是：`Abort "msg"` 在 `/S` 下**不弹窗、立即返回**，
   而 `MessageBox` 在 `/S` 下**照常弹窗并阻塞** → `Start-Process -Wait -PassThru` 永久挂住。
2. **仍然要显式 `SetErrorLevel 1`**：因为「失败 = 非 0」不能依赖默认值。哪天 NSIS 把默认值改成 0
   （或有人把 `Abort` 换成 `Quit`），就会真的变成「报成功 → 删包 → 重启一个白屏的应用」，
   而这类事故在发布后才被发现时排障成本极高。写成显式契约，才是这条修复的价值。

**改法**（两处各加一行，`Abort` 的参数文本不动）：

```nsis
          ${If} $R1 != ""
            ExecWait `"$R1" /install appguid=${WEBVIEW2APPGUID}&needsadmin=true` $1
            ${If} $1 = 0
              DetailPrint "$(webview2InstallSuccess)"
            ${Else}
              MessageBox MB_ICONEXCLAMATION|MB_ABORTRETRYIGNORE "$(webview2InstallError)" IDIGNORE ignore IDRETRY update_webview   ; ← 943
              Quit      ; ← 944：退出码 0
              ignore:
            ${EndIf}
          ${EndIf}
```

**问题有两层，第二层更严重**（→ **已被上面的实测口径取代，见新「问题」段**）：
1. 静默模式下照样弹 `MB_ABORTRETRYIGNORE`，等人点 → 挂死。
2. ~~选「Abort」走到 `944` 的 `Quit` —— 模板里没有任何 `SetErrorLevel`，所以退出码是 0，
   `update.rs` 判成功 → 删包 + 重启，但 WebView2 缺、程序白屏。~~
   **实测更正**：无 `SetErrorLevel` 的中止在 `/S` 下退 **2**，不会被 `ExitCode -eq 0` 误判成功；
   `SetErrorLevel 1` 的作用是把「失败 = 非 0」变成显式契约，不再赌 NSIS 的未文档化默认值。
   **并且这段（本文件 `:938-980`）当前因 `MINIMUMWEBVIEW2VERSION=""` 不参与编译，改它无效。**

**改法**：

```nsis
            ${If} $1 = 0
              DetailPrint "$(webview2InstallSuccess)"
            ${Else}
              ${If} ${Silent}
                ; 无人值守：不能弹窗，且必须让上游知道失败了
                System::Call 'kernel32::AttachConsole(i -1)i.r0'
                ${If} $0 <> 0
                  System::Call 'kernel32::GetStdHandle(i -11)i.r0'
                  System::call 'kernel32::SetConsoleTextAttribute(i r0, i 0x0004)'
                  FileWrite $0 "$(webview2InstallError)"
                ${EndIf}
                SetErrorLevel 1
                Quit
              ${Else}
                MessageBox MB_ICONEXCLAMATION|MB_ABORTRETRYIGNORE "$(webview2InstallError)" IDIGNORE ignore IDRETRY update_webview
                ; 走到这里 = 用户选了 Abort：同样必须置非 0，否则 update.rs 会当成功
                SetErrorLevel 1
                Quit
              ${EndIf}
              ignore:
            ${EndIf}
```

**注意**：`ignore:` 是 `MessageBox` 的跳转标签，加 `${If}/${Else}` 之后它必须仍在 `${Else}` 分支的
作用域内可达（上面的写法把 `ignore:` 放在 `${EndIf}` 之后，`IDIGNORE ignore` 跳过去仍然有效）。
（这段改法保留在 `installer.nsi:938-980`，但**当前构建不编译**；逻辑正确，配了最低版本时才生效。）

## R-1 · `pick_setup` 的 rank 不比版本号

**文件**：`src-tauri/src/update.rs`　**行**：`241-244`

现状：

```rust
let id = a.get("id").and_then(|x| x.as_u64()).unwrap_or(0);
let rank = if name.contains("x64") { 1 } else { 0 };      // ← 只区分有没有 x64
let cand = (rank, name.to_string(), url.to_string(), digest, id);
if best.as_ref().map(|b| cand.0 > b.0).unwrap_or(true) {  // ← 同 rank 保留**先到的**
    best = Some(cand);
}
```

**问题**：同一个 release 里若挂了两个以 `-setup.exe` 结尾的资产，选中哪一个是**不确定的**
（GitHub API 顺序 ≈ 文件名字母序 → `FontManager_2.1.1_…` 排在 `2.1.6` 前面 → **挑到旧的**）。
PRD D6 的命名分工（回退件叫 `-nsis-fallback.exe`）已经从结构上让「两个包」不该出现，
但代码不该依赖发布纪律来保证正确性。

**最小改法**（保持返回类型与调用点不变，只把 rank 换成元组）：

```rust
/// 从资产名里抠 semver：`FontManager_2.1.6_x64-setup.exe` → `(2, 1, 6)`。
/// 抠不到给 `(0, 0, 0)` —— 这样「解析不出版本」的资产永远排在有版本的后面。
/// 前置小写化：`pick_setup` 判后缀时用的是 `to_ascii_lowercase()`，但 `name` 保留原样，
/// 这里若直接按 `"FontManager_"` 剥前缀，遇到小写命名的资产会静默降级成 (0,0,0)。
fn version_triplet(name: &str) -> (u64, u64, u64) {
    let lower = name.to_ascii_lowercase();
    let rest = lower.strip_prefix("fontmanager_").unwrap_or(&lower);
    let head: String = rest
        .chars()
        .take_while(|c| c.is_ascii_digit() || *c == '.')
        .collect();
    let mut it = head.split('.').map(|s| s.parse::<u64>().unwrap_or(0));
    let a = it.next().unwrap_or(0);
    let b = it.next().unwrap_or(0);
    let c = it.next().unwrap_or(0);
    // a == 0 表示「没能解析出版本」（版本号从 0 开始的产品不在本项目的取值范围内）
    if a == 0 { (0, 0, 0) } else { (a, b, c) }
}
```

然后把 rank 那一行改成（**必须显式展平**）：

```rust
// 版本高的优先；版本相同才用 x64 做次级排序。
// 元组比较是按元素字典序，所以 (2,1,6,1) > (2,1,5,1)，且 (2,1,6,1) > (2,1,6,0)。
// ⚠️ 不要写成 `(version_triplet(name), u8::from(..))` —— 那会构造出**嵌套元组**
//    `((u64,u64,u64), u8)`，虽然比较结果碰巧也对，但同时会让 `cand` 的类型变成
//    `(((u64,u64,u64),u8), String, …)`，与下面的类型标注对不上（2026-11-14 实测编译报 E0308）。
let (vmaj, vmin, vpat) = version_triplet(name);
let rank = (vmaj, vmin, vpat, u8::from(name.contains("x64")));
```

`cand.0 > b.0` 与 `best` 的元组类型随之变成 `((u64,u64,u64,u8), String, String, String, u64)`；
其余逻辑一行不用动（`best.map(|b| cand.0 > b.0)` 仍然成立，因为 `cand.0` 仍可比较）。

**验证**（纯单元测试，不需要网络）：
