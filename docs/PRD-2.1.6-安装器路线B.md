## 2. 回归基线：必须保留的行为（20 条）

> 读法：**「2.1.5 证据」是代码事实；「2.1.6 要求」是安装器重写后必须逐条对上的契约。**
> 风险列 = 写错之后的后果等级，P0 表示会造成用户数据损坏或更新链路断裂。

| # | 行为 | 2.1.5 证据（已核实） | 2.1.6 要求 | 风险 |
|---|---|---|---|---|
| B1 | **按用户安装**，默认 `%LOCALAPPDATA%\FontManager` | `tauri.conf.json` 未设 `installMode` → schema 默认 `currentUser`；`installer.nsi` `.onInit` 里 `StrCpy $INSTDIR "$LOCALAPPDATA\${PRODUCTNAME}"`；`hooks.nsh` 注释 "RequestExecutionLevel user" | 默认目录同左；**不申请 UAC 提权**（不写 `requireAdministrator` manifest） | P0（提权=装到 Program Files=数据被迫回退） |
| B2 | **自定义安装目录**（`/D=` 与目录页浏览） | `ZfmDirPre` ②：显式 `/D=` 优先，不做升级锁目录覆盖 | 支持在屏 2 改目录；`/D=<path>` 优先于一切 | P1 |
| B3 | **升级锁目录**：已装过就装回同一目录，不因用户改路径产生两套 | `ZfmDirPre` ③：`ReadRegStr $R0 SHCTX "${MANUPRODUCTKEY}" ""`，非空则 `StrCpy $INSTDIR $R0` 并 `Abort` 本页 | 已存在安装记录（`HKCU\Software\IIEOzo\FontManager` 默认值非空）→ 忽略用户新选目录，`/D=` 仍可覆盖 | P0（漂移=两套字体库+账本，用户看到"升级后数据全没了"） |
| B4 | **目录页写探针**：不可写当场拦，不留半装空壳 | `ZfmDirLeave`：建目录 → 写 `.zfm-probe` → 失败则 `RMDir` 空目录 + MessageBox + 停在当前页 | 等价实现，且**提前到屏 2 的"可写"判定**（对应规格书 §4.7 异常①，红字 + 主按钮禁用） | P1 |
| B5 | **`/S` 全静默**：零 UI、阻塞到装完、成功退出码 0 | NSIS 内建 `Silent`；`update.rs` 用 `Start-Process -Wait -PassThru /S` 并判 `ExitCode -eq 0` | 见 §5 D3。**必须**：无窗口、无 MessageBox、阻塞、0=成功 / 非 0=失败 | P0（退出码错=更新器删包并"静默中止"） |

| B7 | **`/UPDATE`**：内部升级标志，跳过清理与快捷方式重建 | `un.onInit` 读 `/P`、`/UPDATE`；`hooks.nsh` 全部清理逻辑被 `$UpdateMode <> 1` 包住 | 保留并对外可见（卸载器仍接受它） | P0（`/UPDATE` 失效=升级时删用户账本，R-04） |
| B8 | **`/NS` 不建快捷方式** | `.onInit` 读 `/NS` → `$NoShortcutMode`；两个 CreateOrUpdate*Shortcut 里 `Return` | 保留 | P2 |
| B9 | **`/R` + `/ARGS` 装完即运行**（仅 `/S` `/P`） | `.onInstSuccess`：非静默不看 `/R`；`RunAsUser "$INSTDIR\fontmanager.exe" "$R0"` | 保留 | P2 |

## 3. 用户流程

### 3.1 正常路径（全新安装）

```
屏1 欢迎 ──继续──▶ 屏2 位置 ──安装──▶ 屏3 安装中 ──成功──▶ 屏4 完成
```

| 屏 | 进入时发生什么（副作用） | 主按钮 | 次按钮 | 可回退 | 取消/关闭的后果 |
|---|---|---|---|---|---|
| 1 欢迎 | 读注册表判定「是否已安装 / 装在哪」、算空间、探 WebView2 —— **只读，不写盘** | `继续` | `取消` | — | 无副作用退出（未建任何目录）。**退出码 1**（见下方"退出码口径"） |
| 2 位置 | 显示默认目录 + 剩余空间 + 可写判定 | `安装`（不可写/空间不足时禁用） | `返回` | 回屏 1 | 见下行"空目录清理" |
| 2→3 之间 | 建 `$INSTDIR`（可能新建） + 写 `.zfm-probe` 探针 + 删探针 | — | — | — | 探针失败：删掉刚建的空目录（仅当本次创建且为空），停在屏 2 |
| 3 安装中 | 逐文件解包 → 快捷方式 → **最后**写注册表 → 写 `data\` 与标记 | 无（主按钮隐藏，规格书 §4.6） | `取消安装`（二次确认） | 不可回退 | 见 §3.3 取消矩阵 |
| 4 完成 | 无写入；复选框只影响"启动参数 / 是否建桌面快捷方式" | `完成` | `打开安装目录` | — | 关窗。若 `立即运行` 勾选 → 启动 `fontmanager.exe` |

### 3.2 升级路径（已装 2.1.5 → 装 2.1.6）

| 差异点 | 规则 |
|---|---|
| 屏 1 | 状态行上方多一条：「检测到已安装 2.1.x，将直接覆盖安装（推荐），数据与字体库保留。」+「先卸载再装」链接（规格书 §4.7 第 4 条） |
| 屏 2 | **默认只读**：显示注册表里记录的旧目录，不可改（对齐现行 `ZfmDirPre` ③ 的硬规则）。`/D=` 显式指定时仍放行。**要不要整屏隐藏 → §8 Q3** |
| 屏 3 | 存在"取消不可能真回滚"的问题 → 见 §3.3 |
| 全程 | `$UpdateMode = 1` 语义：不清理任何数据、不重建快捷方式、不重装 WebView2 |
| 完成 | 不启动主程序时也要保证：下次启动能走 `<install>\data`（标记与账本都在原地，无需重新迁移） |

### 3.3 取消 / 回滚矩阵（**本版新增能力，也是最容易做成事故的地方**）

> 2.1.5 的现状是：NSIS 在"安装中"页取消，**已写入的文件不清理**（留半装目录，注册表大多还没写）。
> 规格书 §4.6 要求"回滚已写入 → 退出"，所以这是**行为增强**，必须严格限定范围。

| 场景 | 允许取消 | 取消后做什么 | 绝对不许做什么 |
|---|---|---|---|
| 屏 1 / 屏 2 | 是 | 删掉本次可能建的空目录，退出 | 碰任何已存在文件 |
| 屏 3 · **全新安装** | 是（二次确认） | 按「本次写入清单」**倒序**删文件 → 删空目录 → 不写注册表 | 不许 `RMDir /r $INSTDIR`（用户可能已往里放了东西） |
| 屏 3 · **升级覆盖** | 是，但**不回滚** | 停止写入；保留现场；提示「本次安装未完成，请重新运行安装程序完成更新。你原有的数据与字体库未受影响。」；退出码**非 0**；写 `<install>\data\install.log` | 不许删任何既有文件（旧版本已被部分覆盖，删了就是"软件没了"） |
| 屏 4 | 不适用 | — | — |
| `/S`、`/P` 中途失败 | 无 UI | 退出码非 0 + 日志 | 不许弹 MessageBox（无人值守会挂死） |

**退出码口径（2026-11-14 修订，采纳架构侧安全侧取值）**：**只有"装完且装好了"才返回 0，其余一切（用户取消 / 中途取消 / 失败）返回 1。** 理由：退出码唯一的消费者是 `update.rs`（`ps1_script` 判 `ExitCode -eq 0` 才**删包 + 重启**），任何"没装完"的状态都绝不能是 0；GUI 交互安装没人读退出码，返回 1 无副作用。

**判定"全新 vs 升级"的唯一依据**：`HKCU\Software\IIEOzo\FontManager` 默认值是否非空（与 B3 同一处判据，不要另造）。

### 3.4 卸载流程（2026-11-14 新增：卸载界面与安装界面同一套设计）

**版式复用安装器**：同一窗口尺寸 1000×620、无标题栏、圆角、左栏 + 右图同一套版式；左栏内容与状态机换成下面三屏。**不新做视觉稿**（右图是否复用同一张由 Q6 确认）。

| 屏 | 内容 | 主按钮 | 次按钮 | 说明 |
|---|---|---|---|---|
| 1 确认 | 标题「卸载 FontManager」+ 一句「将从这台电脑移除 FontManager。」+ **复选框「同时删除全部数据与字体库」（默认不勾）** + 元信息（安装位置 / 占用空间 / 数据目录） | `卸载` | `取消` | 复选框文案沿用 2.1.5 的 `$(deleteAppData)` 措辞（已披露行为，不改口径）；取消 → 退出码 0 |
| 2 进度 | 状态行「正在移除 · i / n」+ 真实进度 + 日志（最多 5 行，与安装屏 3 同组件） | 无（主按钮隐藏） | 无 `取消` | **卸载不提供取消**（理由见下） |
| 3 完成 | 徽标 + 「卸载完成」+ 一句「你的数据已保留在 <路径>」（勾选删数据时改为「数据已全部删除」） | `关闭` | — | 关窗即退出码 0 |

**入口一致性（四个入口都必须进新界面）**：① 控制面板「卸载程序」② Windows 设置 → 应用 → FontManager → 卸载 ③ 开始菜单卸载项（若存在）④ 直接执行 `UninstallString`。①②④ 本质是同一个 `uninstall.exe`，所以只要它默认进 GUI 三屏即可；**不许**出现"从某个入口进去是旧 NSIS 界面"。

**卸载不提供取消的理由**：卸载到一半取消，白名单删除是不可逆的（已经删掉的插件目录/字体注册项无法恢复），给一个"取消了但东西已经少了一半"的按钮，比不给更糟。屏 2 只显示进度，不显示取消。

**`/S` 与 `/P` 的卸载语义必须保住**（B7、B17）：`/S` 全静默、0/非 0 退出码；`/P` 跳过确认屏但保留进度；`/UPDATE` 一律不清理。这三条是"企业静默卸载"和"升级链"依赖的行为，不能因为换 UI 丢掉。

**产品级硬约束（架构必须满足，非实现建议）**：卸载器**不得**因为 WebView2 不可用而丧失卸载能力 —— 用户完全可能在卸载前先卸掉/损坏 WebView2。此时必须降级为"原生确认框 + 静默卸载"，宁可难看，不许卸不掉。

## 4. 异常态与责任归属

规格书 §4.7 六条照抄（样式与文案以规格书为准），此处补**"路线 B 下由谁负责"**，另补**三条**规格书没写、但路线 B 必然会遇到的（E7–E9）。

| # | 场景 | 谁负责 | 说明 |
|---|---|---|---|
| E1 | 无写入权限（路径框下方红字） | **安装器** | 屏 2 内解决；主应用不参与 |
| E2 | 空间不足（副状态位） | **安装器** | 安装前一次性算出所需空间（payload 解压后总字节：2.1.6 = **23,706,438 B ≈ 23.7 MB**；路线 B = **≈28.6 MB**，因为多了卸载器门面与内核），非估算。**规格书 §4.5 的「约 420 MB」已废弃**（那是把按需下载的运行时算了进来）：屏 1「需要空间」显示 **约 24 MB（2.1.6）/ 约 29 MB（路线 B）**，「包含内容」写 **「程序本体 · 卸载程序」**，运行时只在说明段/副状态出现并注明**「按需下载」**。详见 §9.5 文案口径 |
| E3 | 安装失败（屏 3 状态行 + `重试`） | **安装器** | 重试复用同一进度上下文，日志保留（规格书要求） |
| E4 | 已安装（升级提示 + 「先卸载再装」链接） | **安装器** | "先卸载再装"= 调 `uninstall.exe`（不勾删数据）→ 再回到屏 1 |
| E5 | 磁盘被占用 / 文件锁定（屏 3） | **安装器** | 对应 B10 的 RestartManager："请关闭后重试" |
| E6 | 静默 / 被动模式 | **安装器** | 这不是异常态，是模式分支（§5 D3） |
| **E7** | **WebView2 缺失**（规格书未覆盖） | **安装器，且在 UI 之前** | Tauri 应用靠 WebView2 渲染，缺失时**四屏根本画不出来**。必须在 `main()` 里、Tauri builder 之前用原生注册表检测（B20），缺失 → 原生 `MessageBox`「需要 Microsoft Edge WebView2 运行时，是否现在安装？」→ 官方源安装 → 重启自身。**三个出口**：重试 / 打开微软下载页手动装 / **改用 NSIS 回退件（打开 release 页并说明用哪个文件）**。**不能**做成屏内状态，也**不能**指望主应用兜底（主应用同样依赖 WebView2） |
| **E8** | **数据迁移中途失败**（规格书未覆盖） | **主应用首启**，安装器只能"不添乱" | 迁移逻辑在 `store.rs::migrate_to_data_root`（copy 不 move、先账本后缓存、失败原地不动、`Fallback`/`Fatal`）。安装器的义务是：不删、不搬、不改老位置任何文件。若迁移 `Fatal`，主应用弹明确报错（`store.rs` 已有文案），安装器不重试、不清理 |
| **E9** | **安装器根本起不来**（被杀软删 / 下载不完整 / exe 损坏） | **下载页 + 回退件**，应用内提示兜底 | 这种情况安装器**没有机会自我介绍**，唯一出路是用户知道还有第二个文件（§6 F 组的命名契约）。所以：① release 正文与 README 安装章节固定一段「优先用 `-setup.exe`；若它无法启动，改用 `-nsis-fallback.exe`」；② 应用内「检查更新」失败时提示里带发布页链接并点名回退件 |

**统一原则**：安装器进程**永不**弹原生模态框，除非 ① 屏 2 的可写/空间校验失败（这是页面内状态，不是模态框）② E7 的 WebView2 缺失（此时还没有 UI 可用）。其余一切走页面内状态 + 日志 + 退出码。

## 5. 关键设计决策（结论，不是选项）

### D1 · 进程模型：两个 exe，安装器**不自删**、不落临时目录

> **注意（2026-11-14 变更 3）**：用户追加硬约束「尽量 0 体积占用的 1:1 还原」后，
> 安装器/卸载器的**界面**改由**主程序 exe 的两个入口**承担（`--installer-ui` / `--uninstall-ui`），
> 不再新做一个带 WebView 资源的安装器门面。下表关于"就地运行 / 不自删 / 不落 `%TEMP%`"的结论**仍然成立**，
> 改变的是"谁画界面"。详见 **§9.7**。

| 项 | 结论 |
|---|---|
| **推荐** | 安装器是独立 exe，在**用户双击的那个位置**就地运行，装完**不自删**，也不把自己复制到 `%TEMP%`。主应用 = 另一个 exe，由安装器写入 `$INSTDIR`。 |
| **理由（一句话）** | 按需"复制到临时目录 + 退出后自删"是 dropper/自删除的经典恶意特征，在 Windows Defender 与 SmartScreen 上是**主动加分项**，而它换来的收益（省一个文件）为零 —— 更新器本来就会在装成功后删包（`update.rs` 的 PS 脚本已实现 `Remove-Item` + 重试）。 |
| **风险** | ① 用户的下载/临时目录里会常驻一个 ~30 MB 的包（`update.rs` 在装成功后会自己删临时目录里那份；用户手动下载的那份不归我们管）→ 缓解：发布说明写清"安装包可自行删除"。② 自删能力一旦将来被要求，必须重新评估 SmartScreen 影响。 |
| **签名** | 安装器**必须**与主程序用**同一套**签名方式。现状（`CODE_SIGNING_POLICY.md`）：流水线已支持 SignPath Foundation 免费 OV 签名，但**截至 v1.5.4 全部未启用（未签名发布 + SHA-256）**，是否已配齐 4 个 Secrets 需在 2.1.6 发版前确认（§8 Q1）。**若已启用**：安装器必须走同一 SignPath 步骤（注意证书主体显示为 *SignPath Foundation*，不是 IIEOzo —— 这是免费计划的固有形式，属已知且已声明的现状）。**若仍未启用**：接受"未知发布者"提示，靠 release 正文的 SHA-256 兜底。 |
| **临时目录归属** | 只有在线更新路径会把包放到 `%TEMP%\FontManager-update\`，那由 `update.rs::update_dir()` 决定，安装器**不参与、不清理别处的包**。 |

### D2 · 分发形态：**单文件，不要外层自解压/引导壳**

| 项 | 结论 |
|---|---|
| **推荐** | 用户双击的文件 = `update.rs` 下载的文件 = Tauri 安装器本体 = `FontManager_<ver>_x64-setup.exe`。payload（**只有 2 个文件**：`fontmanager.exe` + 预构建 `uninstall.exe`，合计 23.7 MB，K3）以**内置归档**形式嵌在这一个 exe 里，安装器直接读自己、逐条解出。**不做**外层 NSIS/自解压壳再套内层。NSIS 那份仍在发布，但它是**并列的回退安装器**（D6），不是这层壳。 |
| **理由（一句话）** | `update.rs` 的三条硬契约（文件名 `*-setup.exe`、`-Wait -PassThru` 阻塞、`ExitCode == 0` 即成功）对壳层极不友好：壳必须先装完再退，还要把内层退出码透传回来，任何一处漏掉就得到"退出码 0 但其实没装"的假成功，而更新器会在假成功后**删掉安装包并重启旧版本**。 |
| **代价 / 风险** | ① **体积实测参照**：2.1.6 的 NSIS 包 = **6,516,753 B（6.21 MiB）**（因为运行时不在包内，K3）；路线 B 的 payload 只多一个 `uninstall.exe` 与 UI 资源，量级一致 —— 所以**不要按"几百 MB"设计进度与超时**。② payload 必须支持**随机读 + 按字节进度**（**不是**按文件数：包里只有 2 个文件，按文件计数会让进度条只有 0→50%→100% 一跳，用户会以为卡住 —— 见 §9.5 结论 2）→ 也不整包先解到 `%TEMP%`。③ 规格书示例里的「148 个文件」是设计稿占位，硬编码即错；实际 `{n}=2`。④ 若将来想把运行时打进包，体积 +144 MB，**不建议**（保持按需下载，K3）。 |
| **构建侧硬约束** | 产出物**必须**重命名成 `FontManager_<ver>_x64-setup.exe`（Tauri 默认产物名是 `<productName>_<ver>_x64-setup.exe` = `FontManager Setup_…`，直接上传会让更新器挑到名字里含 `Setup` 的重复项）。且 release 里**以 `-setup.exe` 结尾的只有这一个**（§7 R5）。NSIS 回退件同时发布，但命名为 `…-nsis-fallback.exe`，**故意不以 `-setup.exe` 结尾** —— 见 D6。 |

### D3 · 静默 / 被动由**安装器自身**解析命令行

| 参数 | 语义（与 2.1.5 对齐） | 2.1.6 判定 |
|---|---|---|
| `/S` | 全静默：零窗口、零 UI、阻塞至装完、成功 0 / 失败非 0 | 安装器 `argv` 扫描（大小写不敏感，允许 `/s`）。**不**交给任何外层解析 |
| `/P` | 被动：跳过自绘欢迎页与完成页，保留进度（无 UI 也能跑） | 同上；屏 1/4 不创建窗口，只有进度窗口 |
| `/D=<path>` | 强制安装目录，优先于注册表记录 | 同上；路径含空格时不要求引号（NSIS 习惯：`/D=` 必须放最后且不加引号 —— 保持兼容） |
| `/UPDATE` | 升级标志：不清理、不重建快捷方式、不装 WebView2 | 同上（安装器自己给卸载器转发） |
| `/NS` | 不建快捷方式 | 同上 |
| `/R` + `/ARGS=` | 装完即运行（仅 `/S` `/P` 生效） | 同上 |

**理由（一句话）**：静默路径是无人值守的，只有一个进程能负责"阻塞 + 退出码"，多一层转发就多一种失败模式；而 `/S` 一旦退出码错，更新器会删包、重启旧版、用户完全不知道发生了什么。

**风险**：`/S` 下**任何** MessageBox 都会挂死无人值守安装（含"文件被占用"、"WebView2 装失败"）→ 全部改成写 `<install>\data\install.log`（若 `$INSTDIR` 还不存在则写 `%TEMP%\FontManager-install.log`）+ 非 0 退出码。验收里必须有这一条（§6 B-10）。

### D4 · 卸载器：**行为内核沿用、界面重做**（2026-11-14 修订，原结论已废）

> 原决策「卸载器完全复用旧 NSIS 界面、一行不改」被用户 2026-11-14 的两句话推翻：
> 「卸载界面也需要和安装界面一样的界面设计」。**界面要换，行为不许换。**

| 项 | 结论 |
|---|---|
| **推荐** | 卸载仍是 `$INSTDIR\uninstall.exe`（`UninstallString` 不变，B16），但**界面换成与安装器同一套设计的三屏**（§3.4），**清理行为逐条等价于今天的 `hooks.nsh`**（§6 W1–W12 为验收门槛）。白名单的**实现机制**（Rust 重写 / 保留 NSIS 内核并换壳 / 双入口同一二进制）由架构定，产品只定口径与验收。 |
| **为什么界面必须换、行为不许动** | 卸载是用户对"这个软件干不干净"的**最后一次印象**，旧 NSIS 灰白页与新版安装器放在一起会像两个产品；而清理逻辑一动就可能删掉用户的字体库（R1）。**这两件事风险等级差了三个数量级，所以必须拆开处理。** |
| **为什么不选「复用主应用」**（`fontmanager.exe --uninstall`） | ① 卸载时它自己就是待删文件 —— Windows 不允许删运行中的 exe，必须复制自身到 `%TEMP%` 再重启删除，正好回到 D1 明确要避开的 dropper 特征；② 用户点"卸载"却启动一个完整字体管理器，观感错乱。 |
| **产品级硬约束（不可让步）** | ① **WebView2 不可用时仍必须能卸载**（降级为原生确认框 + 静默清理），不许"卸不掉"；② `/S`、`/P`、`/UPDATE` 三个开关的卸载语义逐条不变（B7/B17）；③ 卸载器与安装器**同版本号、同签名状态**；④ 卸载器不得依赖安装包（装完用户就把 setup.exe 删了）。 |
| **风险** | ① **白名单从 NSIS 搬进 Rust 是最高风险动作**（若架构选这条路）：漏一项=残留，多一项=删用户字体 → 靠 W1–W12 逐条验收 + 与旧 `uninstall.exe` 的**行为对照测试**（同机、同数据、分别跑新旧卸载器，比对文件与注册表差异为空）。② 卸载器体积变大（要带 UI 资源），但仍必须能自删除（`uninstall.exe` 删自己需要临时副本，这是 Windows 的既有约束，不是新问题）。③ 卸载器自身被杀软拦 → 用户"卸载不掉"，比装不上更伤 → 见 R3。 |

### D5 · WebView2：检测放在 Tauri 初始化之前，装完重启自身

| 项 | 结论 |
|---|---|
| **推荐** | 安装器 `main()` 第一段：原生读注册表（与 B20 同路径）→ 缺失/过低时弹**原生** MessageBox → 从微软官方源下载 evergreen bootstrapper 并静默安装 → 重新 `exec` 自身。检测**不**进四屏，**不**进屏内异常态。 |
| **理由（一句话）** | Tauri 窗口是 WebView2 渲染的，缺失时连"错误页"都画不出来 —— 这是唯一允许在 UI 之前用原生弹窗的地方（与 §4 的"永不弹模态框"原则的唯一例外，且已明确列出）。 |
| **风险** | ① 官方源下载在国内网络可能慢/失败 → **三个出口**：重试 / 打开微软下载页 / **改用 NSIS 回退件**（D6、E7、E9），且失败时退出码非 0 + 日志。② `/S` 下不可弹框 → 直接尝试静默安装，失败即非 0 退出。③ 若将来改为内置离线包，安装器体积 +130 MB（不做）。④ **回退件也解决不了"完全离线 + 无 WebView2"**：NSIS 的 `downloadBootstrapper` 同样要联网 → 该场景明确不支持（要支持得带 WebView2 离线安装器，+130 MB，非目标）。 |

### D6 · 双安装路径：主推 + 回退件，靠**命名**而不是靠"人工挑"分工（2026-11-14 新增，替代原 Q2）

| 项 | 结论 |
|---|---|
| **推荐** | 两份都发布，命名与分工如下：**主推** `FontManager_<ver>_x64-setup.exe`（Tauri 安装器，唯一被一键更新使用的文件）；**回退件** `FontManager_<ver>_x64-nsis-fallback.exe`（原 NSIS 安装器，正式发布，不是内部件）。 |
| **关键机制** | 回退件名**故意不以 `-setup.exe` 结尾** → `update.rs::pick_setup()` 的 `ends_with("-setup.exe")` 过滤会天然忽略它，一键更新永远只可能拿到 Tauri 那份。**"更新器挑错文件"这个问题不是靠约定解决的，是靠这个后缀直接让它不存在。** |
| **代价** | 回退件在更新器眼里"不存在"→ 一键更新只能走 Tauri 路径；Tauri 路径失败时，只能靠 E9 的"引导用户去发布页挑另一个文件"，无法自动降级。**这是接受的设计**：自动降级到 NSIS 会带来"静默换了安装器实现"的不可预期，比失败更糟。 |
| **两份产物的等价要求** | 同目录结构、同 13 个注册表值、同 `install_kind` 判定、同卸载器（§6 F2 双路径产物 sha256 逐项相同）—— 否则"回退件装出来的是一台不一样的机器"，后续升级与卸载全部跑偏。 |
| **风险** | ① 回退件长期不跑会腐化（hooks.nsi 与 Tauri 安装器的行为漂移）→ 每次发版两条路径都要过 F2，不允许"只测主推"。② 用户可能只看到回退件（旧链接、第三方转载）→ 说明写清"优先 `-setup.exe`"；不过这不会造成坏结果，只是少了好界面。③ 两份都要签名/都不签名，不能一个签一个不签（R3）。 |

**W 表的"上溯依赖"自查（这类问题在集合 diff 里看不出来——单个值都在，只有跑真实卸载才暴露）**

> 起因：`Installer Language` 那个洞不是"少删一个值"，而是"少删一个值导致**父键的 `/ifempty` 判定失败**"。
> 对所有 `/ifempty` 与"非递归删目录"逐条自查，同一类问题共 **7 条**（AW1–AW7）。

| # | 上溯 / 依赖链 | 触发条件 | 错法的表现 |
|---|---|---|---|
| AW1 | `Software\IIEOzo\FontManager` → `Software\IIEOzo`（两级 `/ifempty`） | 勾选删数据 且 非 `/UPDATE` | 键内**任一值**（默认值 `$INSTDIR`、`Installer Language`）或任一子键没删 → `/ifempty` 静默不删父键 → 残留空壳。**W11b 就是这条** |
| AW2 | **顺序依赖**：必须先删键内所有值/子键，**再** `/ifempty` 上溯 | 同上 | 顺序反了 **NSIS 不报错**，只是上溯不生效 → 只能靠真实卸载 + 注册表导出比对才能发现（F2a 判等档要覆盖"卸载后"这一步，不只是"安装后"） |
| AW3 | `Software\Classes\.S/.P/.L-FontManager`：整键删，**禁止**上溯 | 非 `/UPDATE` | 一旦给 `Software\Classes` 加 `/ifempty`，删的是**系统共用根**（全机器的文件关联都挂在下面）→ 灾难。**明令禁止** |
| AW4 | `...\CurrentVersion\Uninstall\FontManager`：整键删，**禁止**上溯 | 非 `/UPDATE` | 同上，`Uninstall` 是系统共用根。**明令禁止** |
| AW5 | 旧键 `Software\TheHolyOneZ / IIEOzo` 是一个**单层键名**（含空格与斜杠），不是两层 | 非 `/UPDATE` | 按路径拆成 `Software\TheHolyOneZ\IIEOzo` 会删错/删漏 —— 这个键名是历史上 publisher 就叫 `TheHolyOneZ / IIEOzo` 造出来的 |
| AW6 | Rust 重写时 `/ifempty` 的等价语义 = **"无值且无子键才删"**，且必须**逆序上溯** | 若 U6 选 Rust | `RegDeleteKey` 本身只删空键（语义等价），但**顺序要自己保证**；`RegDeleteTree`/`remove` 类的 API 会连非空键一起删 → 直接违反 AW3/AW4 |
| AW7 | **目录同构问题**：`RMDir "$INSTDIR"` 是**非递归**的，依赖前面已把内容删空 | 卸载末尾 | 改成 `remove_dir_all` / `RMDir /r "$INSTDIR"` = 删用户放进安装目录的任何东西（R1 红线） |

### 9.5 文案与进度语义口径（2026-11-14 拍板，覆盖规格书 §4.5 的旧占位文案）

> 为什么必须改：规格书 §4.5 的文案是**照 420 MB / 148 个文件的设计假设**写的，而实测是 **23.7 MB / 2 个文件**。
> 数字对不上时不是"改个数字"，是**这条文案本身失去了表意能力**。以下四条为最终口径（冲突时以本节为准）。

| # | 位置 | 原（规格书 §4.5） | 改为 | 为什么 |
|---|---|---|---|---|
| T1 | 屏 1 状态行 | `准备就绪 · 将写入 148 个文件` | **`准备就绪 · 即将开始安装`**（**删掉文件数**） | `{n}=2` 时「将写入 2 个文件」会让用户怀疑"是不是漏装了"；文件数是实现细节，不是决策依据。用户真正关心的是**多大 / 多久 / 要不要管理员**，这三件事已由「需要空间 约 24 MB」「预计 5 秒 · 无需管理员权限」承载 |
| T2 | 屏 3 状态行 + 进度条 | `正在写入文件 · 34 / 148`（按**文件数**） | **`正在安装 · 12.4 MB / 23.7 MB`**（按**字节**，`tabular-nums`；进度条按字节推进）→ **同时也是验收条款，见下方 T2-AC** | **这是本版最容易做错的一条**：包里只有 2 个文件，按文件计数会让进度条只有 0% → 50% → 100% 两跳，中途长时间不动，用户会以为卡死 → **杀进程 / 强关机，那才是真事故** |
| T3 | 屏 1 元信息 | `包含内容 程序本体 · 字体库 · Python / Node 运行时` | **`包含内容 程序本体 · 卸载程序`**；运行时另起一行或放说明段，写「Python / Node 运行时**按需下载**」 | 安装器**不建**字体库目录（`hooks.nsh` 注释明确"绝不在这里建 字体库 / plugins"），运行时也不在包内 —— 原文案两处误导 |
| T4 | 屏 1 元信息 | `需要空间 约 420 MB` | **`需要空间 约 24 MB`（2.1.6）/ `约 29 MB`（路线 B）** | 实测 23,706,438 B；路线 B 因多出卸载器门面（≈4.5 MB）+ 内核（≈130 KB）升到 ≈28.6 MB。写 420 MB 会让 100 GB 剩余空间的用户看到"空间紧张"的错觉，也可能触发 E2 误报 |

> 屏 4 正文里的 `FontManager 2.1.5 已安装` 是版本占位，实际取 `{v}` = 当前版本（2.1.6）。

#### T2-AC · 屏 3 进度的验收条款（从"文案口径"升格为硬需求，QA 可直接测）

> 为什么升格：这条不是好看不好看的问题 —— 进度条长时间不动，用户会**杀进程或强关机**，那才是真正会坏数据的动作。

| # | 条款 | 判定方法 |
|---|---|---|
| T2-AC1 | **按字节，不按文件**：进度事件的分子分母都是**字节数**（`written_bytes` / `total_bytes`），`total_bytes` = payload 解压后总字节（路线 B ≈28,558,150；2.1.6 = 23,706,438） | 抓 `install://progress` 事件流，断言 `total` 恒等于该值、且**不等于文件数**（2/3） |
| T2-AC2 | **事件密度**：每写入 ≤ 256 KB 必须发一次事件；事件总数 ≥ ⌈total_bytes / 256 KB⌉（23.7 MB → ≥93 次；路线 B ≈28.6 MB → **≥109 次**） | 数事件条数 |
| T2-AC3 | **事件间隔**：正常机器（SSD、关实时保护）相邻事件间隔 **P95 ≤ 300 ms、最大 ≤ 1500 ms** | 事件时间戳统计 |
| T2-AC4 | **UI 单调性**：每 300 ms 采样进度条宽度 `p_i`，必须 ① 单调不减；② 相邻采样**跳变 ≤ 20%**（防"两跳"）；③ **无 ≥ 1500 ms 的完全停滞**（`p` 不变且未到 100%） | 录屏抽帧 + 像素测宽 |
| T2-AC5 | **收尾**：进度到 100% 后 **≤ 200 ms** 切到屏 4（与启动页的 200 ms 口径同源） | 时间戳 |
| T2-AC6 | **不倒退**：取消 / 失败时进度条停在当前值，**不许回退到 0**（回退会让用户误以为"删掉了已装的东西"） | 手工 + 录屏 |
| T2-AC7 | **中断可续算**：取消后重跑，进度从已写字节继续（不回到 0）；依据是 §3.3 要求落盘的"本次写入清单"必须**记字节数**而非只记文件名 | 取消 → 重跑，比较首次事件值 |

**结论 1（team-lead 问的「`{n}=2` 文案怎么办」）→ 直接删掉数字，见 T1。**
不选"改成 2 个文件"：一个 23.7 MB 的安装器说"将写入 2 个文件"，读起来像 beta；也不选"改成 24 MB"：与元信息「需要空间」重复。状态行只承担一件事 —— **"现在到哪一步了"**，数字交给元信息与进度条。

**结论 2（`{n}` 删掉后，屏 3 的 i/n 也必须一起改）→ 按字节，见 T2。**
这条是删数字的连带后果，也是最容易被漏的：屏 3 的分子分母如果还按文件数，2 个文件会让进度条变成两段跳。

|---|---|---|
| `MainBinaryName` | REG_SZ | `fontmanager.exe` |
| `DisplayName` | REG_SZ | `FontManager` |

| `NoRepair` | REG_DWORD | `1` |

> **`EstimatedSize` 已查清，并发现一个既有 bug（2026-11-14）**：
> 模板算法是 `GetSize($INSTDIR, /M=uninstall.exe) + ESTIMATEDSIZE`（`installer.nsi:1025-1028`）；当前渲染出的 `ESTIMATEDSIZE = 23180`（渲染后 `:100`），而本机 2.1.5 装机实测 `EstimatedSize = 23150`。`23150 < 23180` ⇒ 若 2.1.5 打包时同一常量取 23180，`GetSize` 得为负数，不可能 → **这个常量在 2.1.5→2.1.6 之间行为变了（Tauri CLI 版本差异）**，若继续用它出 NSIS 包，`EstimatedSize` 可能翻倍到 ~46,000 KB。
> **路线 B 的处置**：不走这条加法，直接写「实际写入字节 / 1024」。**但路线 B 的真实占用变大了**：`$INSTDIR` 变成 3 个程序文件（`fontmanager.exe` + 门面 ≈4.5 MB + 内核 ≈130 KB）→ 该值从 23150 升到 **≈27.5k–27.9k KB（+19%）**。这是**真实占用变大**，不是打包差异，所以 **容差从 ±5% 放宽到 ±25%**（不要去改小数字去凑旧值）。类型 REG_DWORD、单位 KB 不变。**不阻塞 2.1.6**；但 NSIS 应急通道（回退件）在 2.1.7 前要修掉这条。

> **计数口径**：本文按"卸载项 **13** 值 + 安装记录 **2** 值（默认值 + `Installer Language`）= **15**"计；架构文档按"除默认值外 **14** 个"计 —— 两说法指同一批数据，验收时以**键+值名清单**为准，不要数字数。
>
> ⚠️ **不要误解"13 个值"**：`update.rs::install_kind()` 只读 **2 个字符串值**（A.1 的默认值、A.2 的 `InstallLocation`），不读任何 DWORD。其余 11 个值对「控制面板卸载信息完整」「卸载器能正常工作」是必需的（B-1 验收），但对「一键更新按钮是否出现」**不起作用**。别为了判 `PerUser` 去校验 13 个值。
