# FontManager 交互细节优化（2.4.1）

> 起因（用户 2026-11-19）：**不要炫技的大动效，要「小到几乎看不见、但用起来顺手」的细节。**
> 这份文档先做体检（拿数字说话），再列缺陷，再写本轮改了什么、为什么这么改，最后写**故意没做**的那些。
>
> 判断标准只有一条：**这条改动能不能用「用户会不会因此少一次困惑 / 少一次多余的等待」来解释。**
> 解释不出来的，一律不做——这就是「克制」和「随便加点动画」的分界线。

---

## 0. 一句话结论

FontManager 的**动效架构其实已经不错**（有时间令牌、有双通道减弱动效、Toast 有合并/暂停/动作按钮）。
真正的问题不是「缺动画」，而是**三处漏网**和**一处没跟上业界做法**：

| # | 问题 | 性质 |
|---|---|---|
| 1 | 12 处过渡写死毫秒数，绕过了时间令牌 → **减弱动效对它们完全失效** | 缺陷（可访问性） |
| 2 | 有「时长」令牌，**没有「缓动」令牌** → 136 处过渡各写各的曲线 | 一致性 |
| 3 | 焦点环：**1 处被删掉 + 4 处引用不存在的变量**（等于从来没画出来过）→ 键盘用户看不到自己在哪 | 缺陷（可访问性） |
| 4 | 提示气泡**每次都等满 1 秒**，在工具栏上挨个看按钮时非常拖沓 | 手感（业界做法没跟上） |

## 1. 外部参考：我抄的是哪几条，为什么

不是找「好看的效果」，是找**大厂已经把结论固化成默认值的参数**。

### 1.1 时长：UI 动效的甜区是 150–300ms

Google Material 的动效规范与多数设计系统的实践一致：**低于 100ms 像卡了一下，高于 400ms 像在等**
（[微交互设计实践汇总](https://launchpad-design.co.uk/micro-interactions-that-convert-psychology-behind-small-ui-details/)）。
Linear 走得更极端：**150ms 是它的甜区**，而且明确规定「hover 只用透明度/表面色变化，不做 scale 放大」
（[Linear Style 规格](https://luckymaomi.github.io/ui/styles/linear-style/showcase)）。

**这条对我们的意义**：我们已经有 `--t-micro 100 / --t-quick 180 / --t-state 260`，正好落在区间里。
所以**不需要重新设计时长**，只需要把漏网的补进去。

### 1.2 缓动：一个产品只该有一族曲线

同一批资料里的结论是：**每个产品定义 3 条曲线就够**（进场 ease-out、退场 ease-in、位置变化 ease-in-out），
再多就会出现「两个按钮速度不一样，用户说不出但感觉得到别扭」。
反面教材是「一个代码库里有 14 条不同的缓动曲线」。

**这条对我们的意义**：我们有 5 档时长、**0 条缓动令牌**，过渡里写的是 `ease` / `linear` / `ease-out` 混着来。

### 1.3 提示气泡：第一条要等，后面的不该再等

这是本轮最有意思的一条，业界已经把它做成了**默认参数**，叫 **skip delay**：

- **Radix UI**：首次 `delayDuration` 700ms；**一条关掉后的 300ms 内，下一条立即显示**（`skipDelayDuration`）
- **UserTesting 设计系统**：首次 1 秒；**2 秒内移到下一个按钮，立即显示**；超时则重置
- **Base UI**：`OPEN_DELAY 500` + `SKIP_DELAY 300`

理由说得很好：**第一次延迟是为了确认「你不是路过」；一旦你在挨个看，再等就是纯摩擦。**
（[Radix/Base UI 的 skipDelay 说明](https://layerwise.app/vibe-coding-glossary/tooltip)、
[设计系统里的具体数值](https://design-system.usertesting.com/latest/components/tooltip/specs-ysuLYhB8)）

**这条对我们的意义**：我们的 `HoverHint` 写死 `DELAY = 1000` 且**每次重新计时**——
从「加标签」挪到「固定」要再等满一秒。工具栏有十几个按钮，挨个认一遍要十几秒。

### 1.4 加载：不要为 200ms 的等待闪一下指示器

共识区间：**延迟 150–300ms 再显示，一旦显示至少保持 300–500ms**，否则「闪一下」比不显示更像故障
（[感知性能实践](https://www.augerelabs.com/blog/perceived-performance-in-saas-skeletons-spinners-optimistic-ui)）。

**这条的意义**：我们的扫描已经有确定进度条（不是转圈），本轮不动；记在这里作为后续做「快速扫描不闪进度条」的依据。

### 1.5 撤销优于确认框（本轮只做记录，不改）

NN/g 的结论很明确：**可逆的动作立刻执行 + 给撤销；只有不可逆且严重的才弹确认框**，
因为「确认框点多了用户就不看了」。

**我们的现状是好的**：`ApplyProgress` 已经常驻底部条做「已应用 x/y + 撤销」，
代码注释里也写了「6 秒就消失的 toast 来不及点」。**这条不用改，只是确认它符合业界结论。**

## 2. 现状体检（实测数字，不是印象）

| 指标 | 实测 | 说明 |
|---|---|---|
| `transition:` 声明 | **136 处** | 动效覆盖面不小 |
| 时间令牌 | `--t-micro 100` / `--t-quick 180` / `--t-state 260` / `--t-layout 400` / `--t-scene 600` | 五档，齐 |
| `var(--t-quick)` 使用 | **136 次** | 绝大多数过渡已经走令牌 |
| **缓动令牌** | **0 条** | `--ease-*` 一个都没有 |
| **写死毫秒的过渡** | **12 处**（另有 1 处跑马灯 `--marquee-dur` 属故意例外） | 见下表 |
| `prefers-reduced-motion` 处理 | 5 处 + `[data-motion="reduced"]` 双通道 | 架构是好的 |
| `:focus-visible` 规则 | 17 条 | 多数是 `2px solid var(--accent)`，但 offset 有 1px/2px 混用 |
| 焦点环被移除 | **1 处**（`.settings-hint`） | 缺陷 |
| **焦点环引用了不存在的变量** | **4 处** | `.copy-name` / `.copyright-status-row` / `.license-file-link` / `.license-file-search`，见 D2b |
| `overscroll-behavior` | 10 处 | `.list-scroll`（主列表）**不在其中** |
| 按压态 `:active` | 16 条 | 列表行、网格卡**没有** |

### 2.1 那 12 处漏网的写死时长

它们是**真正的问题**，因为减弱动效的实现方式是「把所有 `--t-*` 令牌压成 1ms」：

```css
:root[data-motion="reduced"] { --t-micro: 1ms; --t-quick: 1ms; /* … */ }
@media (prefers-reduced-motion: reduce) { :root { /* 同上 */ } }
```

写死毫秒的过渡**不读令牌**，所以这些地方在「减弱动效」下**照样跑 90–200ms**：

| 行 | 选择器 | 现状 | 归到 |
|---|---|---|---|
| 486 | `.load-fill` | `width 160ms linear` | `--t-quick` |
| 3590 | 载入遮罩 | `opacity 0.2s linear` | `--t-quick` |
| 4139 | `.settings-hint` | `opacity/color 0.15s` | `--t-quick` |
| 4196 | 设置勾选项 | `border-color/color/background 120ms` | `--t-micro` |
| 6065 | 版权状态行 | `background/color/border-color 0.15s` | `--t-quick` |
| 7112 | 面板淡出 | `opacity 0.2s linear` | `--t-quick` |
| 7346 | 字重名整行 | `background/box-shadow 120ms` | `--t-micro` |
| 9740 | 设置更新条 | `width 0.2s linear` | `--t-quick` |
| 10436 | 面板高度 | `height 110ms` | `--t-micro` |
| 10497 | `.tag-dock-caret` | `transform 110ms` | `--t-micro` |
| 10751 | 淡入层 | `opacity 90ms` | `--t-micro` |
| 10779 | `.tag-caret` | `transform 100ms` | `--t-micro` |

> 顺带一个必须说清的点：**`linear` 不要改成贝塞尔**。进度条填充、滚动指示灯这类「按时间匀速推进」的
> 元素，缓动会让它看起来在「追赶」，反而不诚实。所以这几处只换时长令牌、**保留 linear**。

## 3. 缺陷清单（按性质分级）

### P0 — 有功能性危害，必须修

**D1｜减弱动效在这些地方失效（12 处）**
不是审美问题：开了「减弱动态效果」的用户（前庭功能敏感人群）在这里仍会被 90–200ms 的位移/淡入影响。
**修法**：全部换 `var(--t-*)`，`linear` 保留。

**D2｜设置页提示图标的焦点环被删掉了**
```css
.settings-hint:hover,
.settings-hint:focus-visible { opacity: 1; color: var(--text-secondary); outline: none; }
```
这个元素是 `<span tabIndex={0} role="img">`——**可以 Tab 到，但没有可见焦点**。
键盘用户 Tab 到它时，屏幕上没有任何东西变化（除了淡淡地变亮一点）。
**修法**：`:focus-visible` 补回 `2px solid var(--focus-ring)`，`offset 2px`。

**D2b｜4 处焦点环引用了一个不存在的变量（写这份文档时才发现）**

这是本轮**最值得记的一条**，因为它是「看不出来」的那种坏：

```css
.copy-name:focus-visible { outline: 2px solid var(--accent); }
.copyright-status-row:focus-visible { outline: 2px solid var(--accent); }
.license-file-link:focus-visible { outline: 2px solid var(--accent); }
.license-file-search:focus-visible { outline: 2px solid var(--accent); }
```

`--accent` 在全项目**从未定义过**（只有 `--accent-a` / `--accent-b` / `--accent-glow*`）。
而 CSS 里 `var()` 解析失败不是「回退到上一个值」，而是**整条声明的计算值变成 `unset`**——
`outline` 的初始值就是 `none`。所以这四行写得很像「有焦点环」，实际渲染出来**一个像素都没有**。

> 为什么一直没人发现：它不报错、不警告，代码审查时看 `outline: 2px solid var(--accent)`
> 完全合理，只有真用 Tab 键走到版权页那几行才会察觉「咦，我的焦点呢」。

**修法**：在 `tokens.css` 立显式令牌 `--focus-ring`（深浅两套主题各一条，取强调色 ——
深色 `#d4d4d8` 对近黑底约 11:1，浅色 `#3f3f46` 对白底约 9:1，都远超 WCAG 对焦点指示的 3:1），
4 处 + D2 那处统一改引它。以后再有人写焦点环，也不会再靠猜变量名。

### P1 — 一致性与手感

**D3｜缓动曲线各写各的**
136 处过渡里混着 `ease` / `linear` / `ease-out` / 不带曲线（默认 `ease`）。
用户感觉不到「这条曲线叫什么」，但能感觉到「这个软件有些地方顺、有些地方钝」。
**修法**：立 3 条令牌，先把「高频面」（列表行、按钮、面板）统一。

**D4｜提示气泡每次都等满 1 秒（缺 skip delay）**
**修法**：第一条仍等 1 秒；**一条关掉后 2 秒内**，下一条只等 120ms。

**D5｜主列表滚动会「传染」给外层**
10 个滚动容器都写了 `overscroll-behavior: contain`，唯独 `.list-scroll`（最常滚的那一个）没有。
滚到底继续滚，滚动会链到外层容器，出现整页跟着弹一下的观感。
**修法**：补 `contain`。

**D6｜列表行没有按压反馈**
`.list-row` 有 hover（`--e1`），但按下时**没有任何变化**——点击像是「没被听见」，要等选中态出现才知道点上了。
**修法**：`:active` 加深一档到 `--e2`；已选中行用 `filter: brightness(.97)` 加深，不覆盖选中底色。
**为什么不用 `scale(.98)`**：列表行是网格布局，缩放会让文字在按下瞬间发虚（次像素重排），
而「变深一档」在同一帧就到位，不产生重排。这是「桌面软件」和「网页卡片」的差别。

### P2 — 想过，但这轮不做（附理由）

| 项 | 为什么不做 |
|---|---|
| 空态加「主行动」按钮（搜不到 → 清除搜索；库空 → 导入字体） | **该做**，但要给 11 种空态各配一个动作落点 + 九语文案，属独立一轮。已列进待办。 |
| 自绘 `::selection` | 我们的强调色是**中性灰**（深色 `#d4d4d8` / 浅色 `#3f3f46`），自绘选区会比系统蓝**更难看清**。不做才是对的。 |
| 列表行 `cursor: pointer` | Windows 资源管理器的列表项也是箭头光标。改成手型是「网页味」，不是桌面味。 |
| 数字滚动动画 | 已经有 `.tabular`（等宽数字），数字变化不会抖动。再叠加滚动动画只是装饰。 |
| `scrollbar-gutter: stable` 防抖动 | 我们的滚动条是自绘的、悬停会变粗。强制留槽会永久吃掉 10px 宽度，换来的收益不明显。 |
| 键盘导航（方向键）加动效 | 高频操作加动画 = 每次都慢半拍。业界共识是**方向键导航不加动效**。 |
| 悬停 `translateY(-2px)` 上浮 | Linear 明确把「hover 缩放/上浮」列进 Don't。工具类软件上浮会让密集列表看起来在抖。 |

## 4. 本轮实施（逐条：证据 → 改法 → 怎么验）

### 4.1 缓动令牌（`src/design/tokens.css`）

```css
--ease-out: cubic-bezier(0.16, 1, 0.3, 1);  /* 进场/响应：快起慢收 */
--ease-in:  cubic-bezier(0.4, 0, 1, 1);     /* 退场：慢起快收 */
--ease-std: cubic-bezier(0.4, 0, 0.2, 1);   /* 位置/颜色变化：对称 */
```

- 放 `:root`，**不进减弱动效的覆盖块**——减弱动效压的是时长，曲线压成 1ms 后已无意义。
- 三条就够。再加第四条，就会出现「这条为什么和那条不一样」的问题。

### 4.2 12 处写死时长归零（`src/app.css`）

全部换 `var(--t-micro)` / `var(--t-quick)`，取值就近归并（90/100/110/120 → micro=100，150/160/200 → quick=180）。
**验收：`grep` 写死毫秒数 = 0**（跑马灯那一处除外，它有自己的变量）。

### 4.3 焦点环补回（`src/design/tokens.css` + `src/app.css`）

先立令牌（深浅两套主题）：

```css
--focus-ring: var(--accent-a);
```

再把 5 处（4 处悬空引用 + 设置页提示图标）统一改成 `outline: 2px solid var(--focus-ring)`，
设置页那处补 `offset: 2px` 与 `border-radius: 4px`（和新版卡片头一致，不会看起来像贴了个方框）。

### 4.4 提示气泡 skip delay（`src/design/primitives/HoverHint.tsx`）

```
首次            → 1000ms（不变：确认「不是路过」）
上一条刚关掉 2s 内 → 120ms（新增：挨个看按钮时不该重复付费）
```

- 只有「气泡**真的显示过**并且是**指针移走**关掉的」才计入「热」状态。
  滚动、按键、窗口失焦关掉的不算——那不是「在挨个看」。
- 超时不清状态，直接用时间戳比较（`now - lastClosedAt < 2000`），少一个定时器。

### 4.5 滚动链隔离（`src/app.css`）

`.list-scroll` 补 `overscroll-behavior: contain`，与另外 10 个滚动容器对齐。

### 4.6 列表行按压反馈（`src/app.css`）

```css
.list-row:active:not(.row-selected) { background: var(--e2); }
.list-row.row-selected:active { filter: brightness(0.97); }
```

## 7. 2.4.2 追加（用户截图 + 把遗留做完）

### 7.1 分组行选中没有蓝竖线 —— 根因在「标签配色」那条规则里

用户 2026-11-19 截图指出：点分组后**没有任何选中效果**，而点标签有「文字动一下 + 左侧蓝竖线」。

分组行本来就复用了 `.tag-row` 并加了 `.sel`，所以看起来「应该自动生效」。真正的原因是这一条：

```css
.tag-row:not(.tag-c-none).sel::before { background: var(--tc); }   /* 特异度 (0,3,1) */
```

分组行**没有任何 `tag-c-*` 类**，于是天然命中 `:not(.tag-c-none)`；而分组行没有 `--tc`，
`var()` 解析失败后 `background` 退回初始值 `transparent` —— 而不是「回退到上一条规则的蓝」。
它的特异度又高于 `.tag-row.sel::before`（0,2,1），所以蓝线被**明确地**画成了透明。
同一个原因还让分组行名落到继承色，而不是预期的次级灰。

**修法**：那条规则显式排除 `.coll-row`。
**为什么不给分组行补一个 `tag-c-none`**：那等于把它伪装成「没配色的标签」，
下次标签配色逻辑再改一遍还会踩同一个坑；按「是不是分组行」排除，语义直白。

### 7.2 选中时的「动一下」

- **行名右移 2px**（`translateX`，`--t-micro` + `--ease-out`）。
  只动行名不动右侧计数：计数是 `flex-end` 对齐，跟着动会脱离右边界。
- **竖线改为 120ms 从中心竖向展开**（`scaleY(.35 → 1)`）。原来只有选中态有 `::before`，
  是硬切出现；现在所有行都有一条透明底座，选中时生长。
- 4px 以上被否掉：密集列表里那是「在跳」，不是「动一下」。

### 7.3 空态主行动 —— 只在按下去真能结束时才出现

| 空态 | 按钮 | 动作 |
|---|---|---|
| 搜不到 | 清除搜索 | `setSearch("")` |
| 被筛选菜单筛没了 | 清除筛选 | 新增 `resetFilters()`，一次清 12 个字段 |
| 其它（收藏空 / 某标签空 / 某分组空…） | **不摆按钮** | 内容状态，没有安全默认动作 |

判据写死在代码注释里：**按钮只在「按下去真的会结束这个空态」时出现**。
摆一个点了没反应的按钮，比不摆更差 —— 它会让用户怀疑软件坏了。

「被筛没了」还额外区分了一层：只有命中**筛选菜单**（剧种/格式/特性/来源/字符/变量/
可切换/不完整/授权/版权）才给按钮；标签 / 分组 / 快照这些是**导航**，
清掉它们等于把用户踢回字体库，不是「清除筛选」。

### 7.4 快速扫描不闪进度条

`useFlashGuard(active, delay=150, minMs=320)`：短于 150ms 的操作根本不挂进度条；
一旦挂上至少停 320ms。原来「一进 scanning 就挂」，几十个字体的重扫 200ms 内结束，
底部会闪一下 —— 那一下读起来像出错，比不显示更糟。

### 7.5 焦点环几何令牌化

`--focus-ring-w` / `--focus-ring-offset`。17 处 `:focus-visible` 里 1px 与 2px 混用，
同一屏 Tab 过去粗细一致、距离不一致，看着像没对齐。
